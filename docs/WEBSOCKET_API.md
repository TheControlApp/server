# WebSocket API Documentation

## 📡 **Overview**

The ControlMe WebSocket API provides real-time bidirectional communication for command distribution and control. It supports both anonymous and authenticated connections with a progressive authentication model.

**Endpoint**: `ws://localhost:8080/ws/client`

## 🔗 **Connection Flow**

### 1. **Connect Anonymously**
```bash
# Using any WebSocket client
wscli.exe ws://localhost:8080/ws/client
```

### 2. **Optional Authentication**
```json
{"type":"auth","token":"your_jwt_token_here"}
```

### 3. **Send Commands**
```json
{
  "instructions": [{"type":"std_popup","content":{"body":"Hello World"}}],
  "tags": "general"
}
```

## 🏗️ **Message Formats**

### **System Messages** (Direct Response)

#### Authentication
```json
// Request
{"type":"auth","token":"eyJhbGci..."}

// Response
{"type":"auth_success","message":"Authentication successful","user_id":"uuid"}
```

#### Ping/Pong
```json
// Request
{"type":"ping"}

// Response  
{"type":"pong","timestamp":1759023093}
```

### **Command Messages** (Broadcasted)

#### New Format (Recommended)
```json
{
  "instructions": [
    {
      "type": "std_popup",
      "content": {
        "body": "Your message here",
        "title": "Optional title"
      }
    }
  ],
  "receiver_id": null,
  "tags": "general"
}
```

#### Legacy Format (Backward Compatible)
```json
{
  "type": "std_popup",
  "content": {
    "body": "Your message here"
  }
}
```

## 📋 **Command Structure**

### **Client Sends**
| Field | Required | Type | Description |
|-------|----------|------|-------------|
| `instructions` | ✅ | Array | List of instruction objects |
| `tags` | ✅ | String | Category tags (e.g., "general", "admin") |
| `receiver_id` | ❌ | UUID/null | Optional specific user target |

### **Server Broadcasts**
```json
{
  "id": "uuid",                    // Generated by server
  "instructions": [...],           // From client
  "sender_id": "uuid",            // From authenticated client  
  "receiver_id": null,            // From client or null
  "tags": "general",              // From client
  "status": "pending",            // Set by server
  "created_at": "2025-09-27T...", // Set by server
  "updated_at": "2025-09-27T..."  // Set by server
}
```

## 🔐 **Authentication**

### **Getting JWT Tokens**

#### Register User
```bash
curl -X POST http://localhost:8080/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "username": "testuser",
    "password": "password123",
    "screen_name": "Test User", 
    "email": "test@example.com",
    "random_opt_in": false
  }'
```

#### Login
```bash
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "username": "testuser",
    "password": "password123"
  }'
```

### **Authentication Requirements**

| Feature | Anonymous | Authenticated |
|---------|-----------|---------------|
| Ping/Pong | ✅ | ✅ |
| Basic Commands | ✅ | ✅ |
| Specific User Targeting | ❌ | ✅ |
| Admin Commands | ❌ | ✅ |

## 🛠️ **Error Handling**

### **Common Errors**
```json
{"type":"error","message":"Invalid JSON message"}
{"type":"error","message":"Command must contain at least one instruction"}
{"type":"error","message":"Tags are required"}
{"type":"error","message":"Authentication required for this command"}
{"type":"error","message":"Invalid or expired token"}
```

### **Validation Rules**
- ✅ Instructions array must not be empty
- ✅ Each instruction must have `type` and `content`
- ✅ Tags field is required
- ✅ ReceiverID must be valid UUID or null
- ✅ Authentication required for sensitive commands

- ✅ **Broadcasting**: One-to-many message distribution
- ✅ **Multi-Client Support**: Unlimited concurrent connections
- ✅ **Structured Commands**: Consistent data format
- ✅ **Backward Compatibility**: Legacy messages still supported
